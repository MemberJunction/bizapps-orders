Parties and line extensions

The form stays dumb. Who is at the org, what an event line needs, and the membership window are facts the entity already knows. This is how they surface — not new screens.

Where the logic lives. Bill-to person shortlist = people related to the chosen org (Common Relationship), read on the shared entity — no transaction. Membership service period is computed at confirm inside OrderEntityServer. Event attendee rows are the IS-A Event Order Line (same ID as the line). Check-in is operational, not entry.

3 · What we will not put in the form

  • Check-in lives on Event Order Line but is a door-scan, not order entry.
  • Service period for events comes from Event Product; for memberships from the term the server writes at confirm.
  • Qty > 1 tickets — one attendee block per unit, or a “same attendee” toggle. Build that when we wire the extension, not as a second grid.
